# 实时定位与路径规划

本文档说明 SmartTillEye 中已经整理进 GitHub 仓库的实时定位与路径规划代码。该部分来自已验证的 GPSLogger + 本地 GPS 接收服务 + 高德地图 Demo 链路，并整理为项目内部代码。

## 代码位置

```text
tools/scripts/gps_receiver_local.py
cloud/web_frontend/frontend/static/location.html
cloud/web_frontend/frontend/static/js/location-map.js
cloud/web_frontend/frontend/static/js/app-config.js
cloud/web_frontend/frontend/static/js/app-config.local.example.js
```

## 数据链路

```text
手机 GPSLogger
    ↓ HTTP GET
tools/scripts/gps_receiver_local.py :5001
    ↓ WGS84 -> GCJ-02
/location
    ↓
cloud/web_frontend/frontend/static/location.html
    ↓
高德地图
    ↓
AMap.Driving 路径规划
```

## GPSLogger URL

在手机 GPSLogger 中配置 HTTP 上传地址：

```text
http://<SERVER_IP>:5001/?lat=%LAT&longitude=%LON&time=%TIME&speed=%SPD
```

Windows 本机联调时，前端默认读取：

```text
http://127.0.0.1:5001/location
```

手机上传时，`<SERVER_IP>` 应替换为电脑在同一局域网中的 IP。

## 定位服务

`tools/scripts/gps_receiver_local.py` 监听 `0.0.0.0:5001`，提供两个入口：

- `/location`：前端读取最新定位。
- `/?lat=...&longitude=...&speed=...`：GPSLogger 上传定位。

初始状态下 `/location` 返回：

```json
{"valid": false, "latitude": null, "longitude": null, "speed": null}
```

收到 GPSLogger 数据后，服务将 WGS84 坐标转换为高德地图使用的 GCJ-02 坐标，并返回：

```json
{"valid": true, "latitude": 0, "longitude": 0, "speed": "0.0"}
```

## 一键启动

`tools/scripts/start_system_auto_discovery.ps1` 已整理为同时启动：

- GPS 定位服务：`5001`
- SmartTillEye 后端和前端：`8088`

入口脚本：

```text
tools/scripts/启动系统_自动发现.cmd
```

停止脚本：

```text
tools/scripts/停止系统.cmd
```

## 配置切换

定位 API 地址集中配置在：

```text
cloud/web_frontend/frontend/static/js/app-config.js
```

默认值：

```js
locationApiBase: 'http://127.0.0.1:5001'
```

未来部署到 SC171-V3 时，只需要改为：

```js
locationApiBase: 'http://<SC171_IP>:5001'
```

## 高德 Key

公开仓库不提交真实高德 Key。需要本地运行地图时，复制：

```text
cloud/web_frontend/frontend/static/js/app-config.local.example.js
```

为：

```text
cloud/web_frontend/frontend/static/js/app-config.local.js
```

然后填写本地使用的高德 Web 端 JS API Key 和 Security JS Code。

`app-config.local.js` 已被 `.gitignore` 忽略，避免真实密钥进入 GitHub。
