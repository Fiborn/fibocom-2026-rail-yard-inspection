# SmartTillEye 智能巡检系统技术报告

## 1. 项目概述

本系统面向铁路货运装卸和轨道巡检场景，采用 ESP32 小车作为移动执行端，电脑作为本地边缘服务端和可视化控制端。系统集成小车运动控制、机械臂控制、摄像头视频采集、ONNX YOLO 视觉识别、告警记录和智能 Agent 辅助处置建议。

系统的核心链路为：

`摄像头/视频流 -> 后端视觉接口 -> ONNX YOLO 推理 -> 告警防抖 -> CSV 告警台账与 Agent -> 前端展示`

控制链路为：

`前端控制页面 -> WebSocket /ws/controller -> Spring Boot -> WebSocket /ws/car -> ESP32 -> 电机板/舵机/灯光`

## 2. 后端技术栈

- Java 17 兼容运行环境。
- Spring Boot 3.3.5。
- Spring WebSocket：实现浏览器、后端和 ESP32 的双向实时控制通信。
- Spring MVC：提供视觉识别、告警记录和 Agent 建议接口。
- MyBatis：保留数据库访问扩展能力。
- Maven：负责项目构建和依赖管理。
- CSV 文件台账：按日期保存告警记录，字段包含时间、类别、等级、置信度和检测框坐标。

## 3. 前端技术

前端采用 HTML、CSS 和原生 JavaScript，作为 Spring Boot 的静态资源发布。

主要模块：

- `robot-control.js`：小车按键、W/S/A/D、自动巡检、机械臂二维遥感、夹爪和急停。
- `yolo-detection.js`：摄像头帧采集、后端检测请求、检测框绘制、告警防抖和 Agent 更新。
- `local-camera.js`：浏览器摄像头接入。
- `websocket.js`：控制 WebSocket 连接和重连。
- `onnxruntime-web`：保留浏览器端 ONNX Runtime 依赖，当前识别主链路在后端。

前端控制页面不直接连接 ESP32，而是通过后端统一转发，避免浏览器跨设备直连带来的网络和安全问题。

## 4. 视觉识别模型

模型文件为 ONNX 格式，位于：

`edge_computing/ai_model/railway_yolov8n_model_v1/best.onnx`

类别文件为：

`edge_computing/ai_model/railway_yolov8n_model_v1/classes.txt`

系统将检测类别映射为四类铁路巡检告警：车门异常、道旁异物、人员越界、轨道损坏。后端返回检测框、类别和置信度，前端使用红色矩形框标记异常目标。

## 5. 告警和 Agent 逻辑

告警采用按类型的 30 秒防抖策略。同一种目标在冷却窗口内重复识别时，不生成新的队列记录、不写入 CSV、不重新请求 Agent，当前 Agent 建议保持不变。不同告警类型分别计时，互不影响。

Agent 不调用外部大模型自动编写建议，而是由后端根据：

1. 告警类别；
2. 识别置信度对应的等级区间；
3. 预置运维话术集合；

返回预设建议。这样可以保证答辩演示和现场处置建议稳定、可审计、可复现。

## 6. ESP32 驱动技术

ESP32 通过 UART2 与小车电机控制板通信，通过 UART1 与 ST3215 舵机总线通信。

- 电机板：GPIO16/27，115200 波特率。
- 舵机总线：GPIO18/19，1000000 波特率。
- 舵机 ID：夹爪 11，肩部 12/13，肘部 14，底座 15。ESP32 启动时读取并记住夹爪当前位置，作为“全部回位”和“夹爪回位”的基准位置。
- 小车采用四路 PWM 指令控制，左右转使用两侧差速反向运动。
- 机械臂遥感协议：`@ARM:POSE,base,lift#`。
- `base` 范围为 `0~4095`，`lift` 范围为 `-1024~1024`。
- ESP32 内置运动看门狗，超过约 800ms 没有新的运动指令会自动停车。

## 7. 自动发现网络方案

ESP32 固件只固定保存指定 Wi-Fi 的名称和密码，不保存电脑 IP。上电连入热点后，ESP32 向局域网 UDP `4210` 端口广播：

`SMARTTILLEYE_DISCOVER,8088`

电脑后端收到后回复：

`SMARTTILLEYE_SERVER,8088`

ESP32 使用回复数据包的来源 IP 作为后端地址，再连接 `/ws/car`。因此电脑更换、DHCP 地址变化时不需要修改源码或再次烧录。

## 8. 安全与可靠性

- 前端断开时后端向 ESP32 发送总停止，ESP32 运动看门狗负责兜底停车。
- WebSocket 断线后 ESP32 停止电机、保持机械臂并关闭灯光。
- 机械臂动作目标进行位置范围校验，越界动作被拒绝。
- 告警写入采用后端同步方法，避免并发写入损坏 CSV。
- 自动发现服务使用局域网 UDP，不依赖固定 IP 或公网服务。

## 9. 答辩演示建议

演示顺序建议为：启动指定热点、启动系统、展示 ESP32 在线、操作小车、拖动机械臂遥感、启动自动巡检、展示摄像头识别和红框、展示 Agent 建议、下载告警表格，最后说明自动发现和 30 秒防抖机制。

## 10. 当前限制

- ESP32 与电脑必须处于同一局域网，且热点允许设备间通信。
- Windows 防火墙如果阻止 UDP `4210`，自动发现会失败，需要允许 Java 局域网通信。
- 摄像头识别性能受摄像头分辨率、光照和电脑 CPU 影响。
- 交付包默认使用 Java 17 或更高版本运行后端。
